# IMSaju 기획문서

> 만세력·사주풀이·궁합 웹앱. 이 문서는 무엇을 왜 그렇게 만들었는지를 정리한 것으로,
> 처음 합류하는 사람이 이것만 읽고 맥락을 잡을 수 있게 쓴다.
>
> 최종 갱신: 2026-10-03 · 저장소: [workminkyoung/imsaju](https://github.com/workminkyoung/imsaju)

---

## 1. 제품

생년월일시로 **만세력(사주 원국)** 을 계산해 보여주고, 그 결과를 근거로 **Gemini** 가 풀이를
써 준다. 두 사람의 **직장 궁합**도 본다.

핵심 가치는 재미가 아니라 **신빙성**이다. 사주 서비스는 널렸지만 "왜 그렇게 나왔는지"를
보여 주는 곳은 드물다. 이 앱은 계산 과정을 열어 보인다.

### 설계 원칙 — 계산과 해석의 분리

| 단계 | 방식 | LLM |
| --- | --- | --- |
| 음↔양력 변환, 절기, 4주, 지장간, 십신, 12운성, 공망, 납음, 오행, 대운, 세운 | 서버 내 순수 계산 | **안 씀** |
| 합·충·형·해·파·원진, 궁합 점수 | 서버 내 순수 계산 | **안 씀** |
| 풀이 텍스트 | Gemini 1회 호출 | 씀 |

이 분리가 전부다. 원국을 LLM이 만들면 환각이 섞여 신빙성이 성립하지 않는다.
계산은 같은 입력에 항상 같은 결과를 내고, 검증할 수 있다. 부수적으로 비용도 아낀다 —
만세력만 보고 나가는 사용자는 API 할당량을 0 소비한다.

## 2. 화면과 흐름

```
/                     카드 테이블 (메인)
/saju/[id]            카드 한 장의 사주 풀이
/compatibility?a=&b=  두 카드의 궁합
/admin                풀이 프롬프트 편집 (비밀번호)
```

### 메인 — 카드 테이블

타로 카드 테이블을 레퍼런스로 삼았다.

- **하단**: 사람 카드가 반원으로 펼쳐진다. 끝의 `+` 카드로 추가
- **카드 클릭**: 뒤집히며 「사주보기」와 「수정」이 나온다
- **드래그**: 위쪽 두 칸(A·B)에 올리면 「궁합보기」가 켜진다

사주와 궁합의 진입점이 한 화면에 모여 있다. 카드를 만들지 않고 즉석으로 보는 경로는 없앴다.

### 왜 주소에 카드 id 를 담는가

`/saju/[id]`, `/compatibility?a=&b=` 로 둬서 새로고침해도 유지되고 링크로 공유된다.
상태를 메모리에만 두면 뒤로 가기 한 번에 날아간다.

## 3. 만세력을 믿을 수 있게 만든 방법

만세력 결과가 서비스마다 갈리는 지점은 네 군데다. 각각을 추정이 아니라 계산으로 처리했다.

### 3.1 절기 — 표가 아니라 천문 계산

월주·연주 경계는 음력 달이 아니라 **태양의 겉보기 황경**이 정한다. 근사표를 쓰면 절입일
근처에서 반드시 틀린다. `astronomy-engine` 으로 절입 순간을 초 단위로 구한다.

- 연주 경계: 황경 315° (입춘)
- 월주 경계 12절: 315 입춘 · 345 경칩 · 15 청명 · … · 285 소한
- 절입 시각은 절대 시각이라 타임존과 무관하다. 출생 순간(UTC)과 바로 비교한다

### 3.2 표준시 — IANA tzdb 에 위임

한국 표준시는 여러 번 바뀌었다. 손으로 표를 적으면 반드시 틀린다. Node 내장 ICU 의
tz 데이터베이스에서 그 시점의 실제 오프셋을 가져온다.

| 시기 | 오프셋 |
| --- | --- |
| ~1908 | +08:27:52 (서울 지방 평균시) |
| 1908~1912 | +08:30 |
| 1912~1954 | +09:00 |
| 1954~1961 | +08:30 |
| 1955~1960 여름 | +09:30 (서머타임) |
| 1987~1988 여름 | +10:00 (서머타임) |
| 1961~ | +09:00 |

### 3.3 진태양시 — 경도 보정

```
localMeanTime = utcInstant + (longitude / 15) hours
```

서울(126.9784°E)은 한국 표준시 대비 **−32분**. 표준시가 +8:30이던 시기에도 분기 없이 맞는다.
균시차(±16분)까지 반영하는 옵션도 있다.

### 3.4 관법은 숨기지 않고 옵션으로

결과가 갈리는 마지막 원인은 계산 오류가 아니라 **유파 차이**다. 드러내면 오히려 신뢰가 는다.

- 야자시(23시 이후 일주를 넘길지)
- 진태양시 보정 방식
- 음력 윤달 — 한국 음력은 중국 농력과 윤달 위치가 다르다(KASI 기준)
- 시각 미상 → 시주를 비우고 3주만

### 3.5 계산 근거를 공개

적용된 표준시 오프셋, 서머타임 여부, 보정량, 월주 기준 절입 시각을 결과 화면에서 보여준다.
**과정을 열어 보이는 것이 곧 신빙성의 근거다.**

> 이 패널에는 생년월일이 그대로 들어 있다. 카드가 그 브라우저에만 있으므로 바로 보여 준다(6절 참고).

## 4. 궁합

같은 원칙이다. 합·충·형·해는 고정된 표라서 계산하고, Gemini 는 해석만 한다.

**보는 것**: 일간끼리의 천간합·충과 십신 친화도, 연·월·일·시 지지의 육합·삼합·방합·충·형·해·파·원진,
오행 보완도.

**자리별 가중치** — 직장 관계를 보므로 사회 활동 영역인 월지를 일지보다 높게 둔다.

| 자리 | 가중치 | 이유 |
| --- | --- | --- |
| 일간 | ×3.0 | 두 사람 본질이 직접 만나는 자리 |
| 월지 | ×2.0 | 사회 활동과 직업 영역 |
| 오행 보완 | ×2.0 | 서로 부족한 기운을 채워 주는 정도 |
| 연지 · 일지 | ×1.5 | 사회적 위치 / 내면의 친밀도 |
| 시지 | ×1.0 | 실무와 결과 |

점수만 던지지 않는다. **어느 자리에서 어떤 관계로 몇 점이 나왔는지 전부 공개**하고 배점
규칙도 화면에서 펼쳐 볼 수 있다. 한 자리의 점수는 −5~+5 로 자른다.

### 관계 설정은 수치를 바꾸지 않는다

상사-직원 · 선임-후임 · 동료를 **방향까지** 받는다(다섯 가지). 같은 십신도 누가 위인지에
따라 정반대로 읽히기 때문이다.

다만 **관계는 점수에 영향을 주지 않는다.** 관계에 따라 가중치를 흔들면 점수의 근거를
설명할 수 없어진다. 관계는 프롬프트에만 들어가 해석의 관점을 정한다.
이 결정은 테스트로 고정돼 있다.

## 5. 사람 카드

궁합은 같은 사람을 반복해서 비교하므로 카드를 저장해 두고 골라 쓴다.

```ts
interface StoredProfile {
  id: string;
  label: string;      // 카드에 보이는 이름
  memo?: string;      // "ID팀 사원" 같은 메모
  input: SajuInput;   // 생년월일시 — 이 브라우저에만
  createdAt: number;
  updatedAt: number;
}
```

- **저장소**: 브라우저 localStorage (`src/lib/profiles.ts`). 서버에는 두지 않는다
- **보관**: 마지막 사용 후 **30일**이 지나면 브라우저에서도 지운다 (`PROFILE_TTL_DAYS`)
- **초기 카드**: 없다. 처음 쓰는 브라우저는 빈 테이블에서 시작한다

## 6. 개인정보 — 가장 신경 쓴 부분

카드에는 **타인의 생년월일**이 들어간다. 로그인이 없으므로 "누가 무엇을 볼 수 있는가"를
먼저 정했다.

| 무엇을 | 어떻게 |
| --- | --- |
| 카드 저장 | **이 브라우저에만.** 서버·DB 에 남기지 않는다 |
| 사주 화면 | 브라우저가 직접 계산한다. 서버로 나가지 않는다 |
| 풀이·궁합 요청 | 입력을 실어 보내고, 서버는 계산에만 쓰고 버린다 |
| 궁합 응답 | 입력 원문·계산 근거·대운·세운·**생년**을 모두 뺀 축소본 |
| 보관 기간 | 마지막 사용 후 30일이 지나면 브라우저에서도 지운다 |

### 솔직히 말해 둘 한계

- **사주 네 기둥 자체가 생년월일을 상당히 좁혀 준다.** 만세력을 보여 주는 이상 피할 수 없다.
  평문으로 건네지 않는 선까지만 했다
- **같은 브라우저를 쓰는 사람은 카드를 그대로 본다.** 공용 PC 에서는 30일 보관 기간
  동안 다음 사람이 생년월일까지 볼 수 있다
- 풀이를 요청하면 만세력이 Gemini API 로 나간다. 저장 방식과 무관하게 같다

## 7. LLM 연동

### 모델 폴백 체인

무료 티어의 실제 지형을 재 보니 ([docs/gemini-findings.md](gemini-findings.md)):

- **Pro 계열은 429** 로 사실상 사용 불가
- **최신 flash 계열은 503** 이 상시적 (`gemini-3.8-flash` 는 5회 연속 실패)
- **lite 계열만 안정적**
- 목록에 있어도 못 쓰는 모델이 있다 (`gemini-2.5-flash` 는 404)

그래서 품질 높은 순으로 시도하다 실패하면 내려가는 **폴백 체인** + 실패한 모델 **60초 쿨다운**.
스트리밍 도중 끊긴 모델도 쿨다운 대상이라 「다시 생성」이 같은 모델에 또 걸리지 않는다.

**중간에 끊긴 응답은 완성된 것처럼 보여주지 않고 잘렸다고 알린다.** 무료 티어에서는 실제로
자주 끊긴다.

### 프롬프트

두 종류(개인 사주풀이 / 궁합)를 `/admin` 에서 편집한다. 말투·목차는 운영자가 정하는
영역이고, 코드가 아니라 **편집 가능한 템플릿**에 있어 배포 없이 바꿀 수 있다.

프롬프트에 데이터를 꽂는 변수가 빠지면 **에러 없이 조용히** 만세력 없는 풀이가 나간다.
실제로 한 번 발생했고, `tests/prompt.test.ts` 가 이를 막는다.

## 8. 검증

```bash
npm test        # 173건
npm run check:gemini
```

| 테스트 | 무엇을 지키는가 |
| --- | --- |
| `crosscheck` | `lunar-javascript` 와 1900~2050년 **무작위 2,000건** 4주 완전 일치 |
| `solarTerms` | 공표 분점·지점과 1분 이내, 독립 구현과 2분 이내 |
| `timezone` | 표준시 이력 · 서머타임 · 진태양시 · 균시차 |
| `luck` | 대운 순행/역행 · 간지 배열 · 시작 연도(독립 구현 대조) |
| `chart` | 입춘·자시 경계 · 음력 윤달 · 시각 미상 |
| `compatibility` | 합·충·형·해 표가 **대칭이고 12지지를 빠짐없이 덮는지** |
| `validate` | 잘못된 입력을 **조용히 다른 값으로 바꾸지 않는지** |
| `profiles` | 목록에 생년월일이 새지 않는지 · 무차별 대입이 막히는지 |
| `prompt` | 템플릿 변수 누락 · 원국 근거 지시 · 안전 규칙 |

**검증 철학**: 표를 손으로 적으면 반드시 오타가 난다. 그래서 개별 사례뿐 아니라 **표의
구조**를 검사한다 — 육합은 두 인덱스 합이 12로 나눈 나머지 1, 충은 차이가 6, 방합은
연속된 세 지지. 규칙성이 깨지면 바로 걸린다.

## 9. 배포와 이식성

특정 호스팅에 묶이지 않는다. 표준 Next.js 만 쓰고 `vercel.json` 은 일부러 두지 않았다.

- **Vercel**: GitHub 저장소 연결 → 환경변수 입력 → 푸시할 때마다 자동 배포
- **도커**: `Dockerfile` 포함. 볼륨을 붙이면 프롬프트·카드가 남는다
- **헬스체크**: `GET /api/health` — 타임존·절기·음력·전체 파이프라인을 **실제로 실행**해 보고
  결과를 말한다. "ok"를 적어 두기만 하면 엔진이 죽어도 초록불이 켜진다

필수 환경변수: `GEMINI_API_KEY`, `ADMIN_PASSWORD`,
그리고 서버리스면 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`.
전체 목록은 [docs/deployment.md](deployment.md).

## 10. 겪은 함정 (다시 밟지 않기 위해)

| 증상 | 원인 | 교훈 |
| --- | --- | --- |
| 배포본에서 만세력 라우트가 전부 500 | `serverExternalPackages` 로 뺀 `astronomy-engine` 의 ESM 빌드만 번들돼 CJS 로 읽다 실패 | 로컬·도커·격리 standalone 모두 통과했다. **배포본이 직접 말하게** 만들어야 잡힌다 |
| 관리자 로그인이 조용히 실패 | 관리자 응답에 `Cache-Control`·`Vary: Cookie` 가 없어 CDN 이 401 을 캐시 | 인증 응답은 반드시 `no-store` |
| 로그인됐는데 화면이 아무 말 없음 | 401 을 조용히 삼킴 | **실패를 삼키면 디버깅이 불가능해진다** |
| 프롬프트에서 만세력이 통째로 빠짐 | 템플릿 재작성 중 변수 누락 | 에러 없이 조용히 망가지는 종류 → 테스트로 고정 |
| 부채꼴 양끝 카드가 잘림 | 아래 축 회전은 바깥 카드를 **내린다**(올리는 게 아니라) | 기하는 머리로 말고 화면으로 확인 |
| 좁은 화면에서 카드 이름이 안 보임 | 반지름을 줄이자 간격이 카드 폭보다 작아짐 | 반지름을 "드러날 폭"에서 역산 |
